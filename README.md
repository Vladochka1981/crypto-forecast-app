# 📈 Crypto Forecast App

**Прогнозирование курсов криптовалют с помощью машинного обучения (Attention-GRU и ARIMAX-LSTM).**

Проект представляет собой локальное веб-приложение (FastAPI + Jinja2 + Lightweight Charts), упакованное в Docker с использованием базы данных PostgreSQL.

## 🧠 Что внутри
### Архитектура (Трёхуровневый монолит)
*   **Presentation (Слой представления):** FastAPI, Jinja2, Lightweight Charts.
*   **Business (Бизнес-логика):** Оркестратор, FeatureEngineer, Предикторы, ACI.
*   **Infrastructure (Инфраструктура):** Async DatabaseRepository (PostgreSQL), DataCollector, CacheManager, Scheduler.

### Модели
1.  **Attention-GRU:** MIMO-модель (5 выходов). Эффективна на горизонтах 4ч и 72ч
2.  **ARIMAX-LSTM:** ARIMAX(4,1,5) + LSTM на остатках. Эффективна на горизонтах 12ч, 24ч, 48ч,
*   **Модельный селектор:** по умолчанию выбирает лучшую модель для каждого горизонта (4ч, 12ч, 24ч, 48ч, 72ч).Можно переключать вручную для выбора модели. 

### ACI (Adaptive Conformal Inference)
Вместо фиксированных интервалов используется онлайн-адаптация: `alpha_t` обновляется после каждого прогноза, обеспечивая покрытие ~95% даже на волатильном рынке.

## 💻 Требования
- **Git** + **Git LFS** (https://git-lfs.com; после установки один раз выполните `git lfs install`).
  Внимание: файлы моделей (.keras, .pkl) хранятся через Git LFS. Без установленного LFS
  клонирование вернёт файлы-заглушки вместо моделей, и приложение не запустится.
- **Docker Desktop** (рекомендуется с WSL 2 для Windows; в настройках выделите минимум 4 ГБ RAM).
- **Python 3.12+** — только для ручного запуска миграции (шаг 3).
- Свободное место на диске: **~10 ГБ**.

## 🚀 Быстрый запуск (Windows, в один клик)

**Перед запуском откройте Docker Desktop** (Пуск → «Docker Desktop») и подождите,
пока в системном трее (правый нижний угол экрана, иконка кита) не появится зелёный
индикатор. Docker должен быть запущен заранее.

Далее скрипт `start.bat` делает всё автоматически: создаёт конфиг, поднимает
контейнеры Docker, ждёт готовности базы и загружает в неё данные. От вас нужно
только склонировать проект.

### Шаг 1. Установите Git LFS (один раз)

Файлы моделей (.keras, .pkl) хранятся через Git LFS. Без него клонирование вернёт
файлы-заглушки вместо моделей, и приложение не запустится.

1. Откройте PowerShell (Пуск → наберите «powershell»).
2. Установите: `winget install GitHub.GitLFS`
   *(если winget недоступен — скачайте установщик с https://git-lfs.com и запустите его)*
3. **Закройте окно PowerShell и откройте заново** (иначе команда не будет найдена).
4. Проверьте: `git lfs version` — должна появиться версия, например `git-lfs/3.5.1`.
5. Активируйте (один раз на этом компьютере): `git lfs install`

### Шаг 2. Склонируйте проект

В том же окне PowerShell выполните две команды подряд (PowerShell открывается
в вашей домашней папке — проект появится там):

`git clone https://github.com/Vladochka1981/crypto-forecast-app.git`
`cd crypto-forecast-app`

Git создаст папку `crypto-forecast-app` в текущей директории (по умолчанию —
`C:\Users\<ваше_имя>`) и скачает туда проект, включая модели (~700 МБ, несколько минут).
Приглашение терминала должно выглядеть так: `PS C:\Users\<ваше_имя>\crypto-forecast-app>`.

### Шаг 3. Запустите приложение

Дважды кликните по файлу `start.bat` (он лежит в корне папки проекта). Docker Desktop должен быть уже запущен.

Скрипт сам:
- создаст `.env` из шаблона — при первом запуске спросит ключ FRED API
  *(Если ключа нет — просто нажмите Enter. Приложение запустится, прогнозы будут работать,
но карточка **Macro** (S&P 500, VIX, нефть и т.д.) не будет обновляться и останется на
последней дате из базы. Модели используют эти данные как признаки, поэтому точность
прогноза может немного снизиться.)*

- соберёт образ и поднимет контейнеры (первый запуск 10–20 минут —
  Docker качает библиотеки TensorFlow и модели; последующие запуски быстрые);
- дождётся готовности PostgreSQL и перенесёт в него данные из SQLite;
- откроет приложение в браузере: **http://localhost:8000/**

Когда в консоли появится `✅ Приложение успешно запущено!` — всё работает,
браузер откроется автоматически.

### Шаг 4. Остановка (когда закончили работу)

В папке проекта выполните:

docker compose down



## 🛠️ Ручной запуск (Linux / macOS / любой терминал)

Если вы работаете не на Windows или предпочитаете управлять контейнерами вручную.
Git LFS нужен и здесь — клонирование описано в «Быстром запуске», шаг 1.

### Шаг 1. Подготовка окружения
1. Склонируйте проект (см. «Быстрый запуск», шаг 2 — Git LFS обязателен).
2. В корне проекта найдите файл `.env.example`. Скопируйте его и переименуйте в `.env`:
   `Copy-Item .env.example .env`
3. Откройте `.env` текстовым редактором. Если у вас есть ключ от FRED API, впишите его в строку `FRED_API_KEY=`. Если ключа нет — оставьте пустым. *Про то, как работает приложение без ключа, — см. «Быстрый запуск», шаг 3.

### Шаг 2. Запуск контейнеров
Откройте терминал (PowerShell) в папке проекта и выполните:
`docker compose up -d --build`
*Первый запуск займёт 10–20 минут (скачиваются TensorFlow и модели), последующие — быстрые.*

Дождитесь статуса `healthy`:
`docker compose ps`
Вы должны увидеть `crypto-app` и `crypto-postgres` со статусом `Up (healthy)`.

### Шаг 3. Загрузка базы данных (после первого запуска)
После первого запуска база PostgreSQL будет пустой. В папке `data/` лежит файл `crypto.db` (SQLite) с полной историей — переносим его в Postgres:
`docker compose exec -T app python scripts/migrate_sqlite_to_pg.py`
*Скрипт перенесёт 15 000+ свечей, Fear & Greed, ончейн- и макро-данные, примерно за минуту.
Скрипт можно запускать повторно, данные не продублируются.*

**Проверка:**
`docker compose exec postgres psql -U crypto -d crypto -c "SELECT COUNT(*) FROM klines;"`
Должно быть ~15000.

### Шаг 4. Открытие приложения
Откройте в браузере: **http://localhost:8000/**---

## 🛠️ Решение частых проблем (Troubleshooting)

**❌ Ошибка `input/output error` или Docker не запускается:**
Это проблема виртуального диска Docker Desktop на Windows.
1. Зайдите в Docker Desktop → **Troubleshoot** → **Clean / Purge data** (выбрать WSL 2).
2. Запустите `docker compose up -d --build` заново.

**❌ Ошибка `Missing feature SP500_lag6` при прогнозе:**
Макро-данные не загрузились. Повторите **Шаг 3** и перезапустите:
`docker compose restart app`

**❌ Карточка Fear & Greed пустая:**
Приложение закэшировало пустой ответ. Удалите кэш и перезапустите:
`docker compose exec app rm -f data/cache/fng.json`
`docker compose exec app rm -f data/cache/price.json`
`docker compose restart app`

## 📂 Структура проекта
*   `app/` — исходный код (FastAPI, ML-модели, бизнес-логика).
*   `data/models/` — обученные модели, ACI-состояния, метрики.
*   `data/crypto.db` — резервная копия данных (SQLite) для миграции.
*   `scripts/migrate_sqlite_to_pg.py` — скрипт миграции данных.
*   `docker-compose.yml`, `Dockerfile` — конфигурация для Docker.
*   `init_postgres.sql` — схема базы данных.
